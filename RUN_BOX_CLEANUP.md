# EC2 run-box cleanup and reconciliation

The worker calls `migrateRunBoxCleanup(db)` during setup and `reconcileAwsRunBoxes(db, provider, { workerId, requestStop })` on startup and on each poll. The `requestStop` argument is the job-store `requestRunBoxStop` operation. The reconciler is internal to the backend and requires the scoped EC2 worker role; it is not a browser endpoint.

Each pass compares approved SQLite jobs with EC2 instances tagged `Project=AgentCloudDemo`, `AgentCloudAutoExpire=true`, and `AgentCloudJobId`. A missing or invalid deadline, an expired deadline, a stop request, or a failed job starts termination. A tagged instance with no matching job is recorded as an orphan and terminated. Job IDs, instance IDs, and EBS volume IDs are persisted in `run_box_cleanup` before termination so a worker restart can continue checking release.

`stopped` is recorded only after EC2 reports the instance terminated or absent **and** every previously observed EBS volume is deleted. A different worker's active lease delays the job state transition until that lease expires, even if EC2 cleanup has already completed. EC2 instance absence without known volume IDs leaves a visible `retry` cleanup record and failed job for operator investigation. A provider or EBS error leaves the cleanup record in `retry`; the next worker pass tries again. The Terraform EventBridge/Lambda expiry guard independently requests termination for expired tagged instances, but it does not update the job database or prove EBS deletion. Reconciliation supplies that evidence.

The worker should run this pass before claiming a new allocation, then repeat it on each poll. Only the worker/provider may issue AWS calls. The local SQLite contract supports one worker; shared production workers need a transactional reconciliation lease to prevent concurrent termination attempts.

A stop requested before any EC2 resource existed (for example an `aws-cpu` job stopped while queued when no CPU worker was configured) is closed by the reconciler with the reason "Stopped before allocation; no EC2 resources exist" and evidence `job:never-allocated:<job>:ec2-inventory-empty` (HAC-166). It closes only when no worker holds the job's lease, no managed instance (from any install) or managed EBS volume carries its job ID, and it has no cleanup record. If a worker ever claimed it for launch, it also needs 15 quiet minutes, no RunInstances error in its history (the deterministic-rejection rule above owns that case), and no managed volume without a job tag; its evidence is then `job:no-launch:<job>:ec2-inventory-empty`. Before this, such a job stayed `stopping` and the single-active AWS guard refused every new AWS request. Runpod already closes never-created jobs (`runpod:never-created:<job>`); docker-local stops are completed by the Docker worker itself.

## Owner force stop (HAC-168)

AWS and Runpod each allow one non-`stopped` job at a time across every project, so a `failed` job or one stuck in `stopping` blocks new environments. A project owner can use **Force stop** on the Environments page (`POST /api/run-boxes/<id>/force-stop` with `{ projectId }`) for any job that is failed, stopping, or already has a stop requested. It records `force_stop_requested_at` and `force_stop_requested_by` on the job and a transition attributed to the owner, then does one of two things:

- **Nothing can exist** (no worker ever claimed the job, no provider resource ID, no active lease): the job is closed at once with evidence `job:never-allocated:<job>:force-stop`.
- **A machine may exist**: a normal stop is requested, and the job stays in place, still blocking new requests, until the worker and this reconciler terminate the instance or Pod and record release evidence. The page shows "Termination requested". Force stop never marks a possibly launched machine `stopped` without that evidence. An AWS job that failed before launch still waits the 15 quiet minutes above; the owner's stop or force-stop click does not restart that wait.

When the guard refuses a request, the error names the blocking environment's project and state only if the caller belongs to that project; otherwise it says the environment is in another project.
